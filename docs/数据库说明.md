# 数据库说明

> 面向初学者：这个项目的数据存在哪、长什么样、怎么保证不丢。

## 1. 数据文件在哪里

| 环境 | 位置 |
|---|---|
| 正式版（Velopack 安装） | `%LOCALAPPDATA%\ProjectFocusManager\data\focus.db` |
| 第一级不可写时 | `%APPDATA%\ProjectFocusManager\data\focus.db` |
| 都不可写时（兜底） | 程序 exe 同目录的 `data\focus.db` |

判断逻辑在 `src/FocusManager.App/AppPaths.cs`：三个候选目录依次尝试「能建目录 + 能真的写入探针文件」才算数。正式版装在 `%LOCALAPPDATA%` 下，**数据目录和程序目录是分开的**——Velopack 升级会整个替换程序目录，但数据不受影响。

> 本开发机比较特殊：`%LOCALAPPDATA%`、`%APPDATA%` 被 ACL 拒绝，所以开发时数据落在第三级 `bin\...\data\`。正常用户的机器只会用第一级。

同目录下还有：

- `focus.db-wal` / `focus.db-shm`：SQLite WAL 模式的伴生文件，程序正常退出时会合并回主库，**不要手动删**。
- `backups\`：手动备份和升级前自动备份都放在这里。
- `WebView2\`：内置 ChatGPT 页面的浏览器用户数据（登录状态在这里）。
- `logs\`：全局异常日志。

## 2. 连接参数（src/FocusManager.Core/Data/DatabaseService.cs）

| PRAGMA | 值 | 为什么 |
|---|---|---|
| `journal_mode` | `WAL` | 写入不阻塞读取；崩溃后靠 WAL 恢复，不会整库损坏 |
| `synchronous` | `NORMAL` | WAL 模式下的推荐档位，兼顾安全与速度 |
| `busy_timeout` | 5000 | 另一个连接短暂持锁时等待 5 秒而不是立刻报错 |
| `foreign_keys` | ON | 级联删除真的生效（删项目连带删掉会话、段落、暂停记录、想法、心跳） |

- 版本号：`PRAGMA user_version`，当前 `TargetSchemaVersion = 2`。
- **时间一律存 UTC**，格式 `yyyy-MM-dd'T'HH:mm:ss.fffffff'Z'`，显示时才转本地时间。存本地时间会在换时区/夏令时后算错时长。

## 3. 表结构（v1 + v2）

v1 由 `ApplyV1` 建 8 张表、6 个索引；v2 由 `ApplyV2` 补 2 张表（项目辅助程序、会话程序快照）和 3 个索引。都在 `src/FocusManager.Core/Data/Migrations.cs`。

### Projects — 项目

| 列 | 说明 |
|---|---|
| Id | 主键，自增 |
| Name / Description | 名称（≤200 字）、说明 |
| CreatedAtUtc | 创建时间（UTC） |
| IsArchived | 归档标记 |
| TotalEffectiveSeconds | **累计有效秒数缓存**。真实值随时可由 FocusIntervals 求和重算 |

### Applications — 登记的学习应用

| 列 | 说明 |
|---|---|
| Name | 显示名 |
| ExecutablePath | 可为空字符串——预置的 Obsidian/百度网盘/CCtalk 只靠进程名识别 |
| ProcessName | 窗口识别用的进程名（如 `Obsidian`） |
| IsBuiltIn / IsEnabled | 是否预置 / 是否启用 |

### FocusSessions — 一次专注会话

| 列 | 说明 |
|---|---|
| ProjectId | 外键 → Projects，级联删除 |
| PrimaryApplicationId | 本轮选的主应用，可空；应用被删时置 NULL（不删会话） |
| StartedAtUtc / EndedAtUtc | 结束时间为空表示会话未结束 |
| Status | running / paused / completed / aborted / recovered |
| EffectiveSeconds | 有效秒数缓存（唯一真相是 FocusIntervals） |
| PausedSeconds / PauseCount | 暂停总秒数、暂停次数（暂停不计入有效时间） |
| ProgressNote / ReflectionNote | 结束总结：本轮完成了什么 / 心得 |

### FocusIntervals — 每段有效专注（唯一真相）

| 列 | 说明 |
|---|---|
| SessionId | 外键 → FocusSessions，级联删除 |
| StartedAtUtc / EndedAtUtc / DurationSeconds | 一段连续有效专注 |

**设计要点**：暂停、崩溃、恢复都只影响「段」。会话表里的 EffectiveSeconds 只是缓存，任何时候都能从段求和重算，不怕缓存被写坏。项目页的累计时间重算也走同一条路。

### PauseRecords — 每次暂停

| 列 | 说明 |
|---|---|
| SessionId | 外键，级联删除 |
| Reason | 暂停原因（必填） |
| EndedAtUtc / DurationSeconds | 为空表示仍在暂停中 |

### IdeaNotes — 随手记想法

| 列 | 说明 |
|---|---|
| ProjectId | 外键 → Projects，级联删除 |
| SessionId | 可空；专注中记下的自动关联当前会话，平时记的为 NULL。会话被删时置 NULL（想法保留） |
| Content / Status | 内容；pending / done |
| CompletedAtUtc | 标记完成的时间 |

### AppSettings — 设置（键值对）

现有键：`Theme`、`PauseReminderMinutes`、`CloseAction`。

### SessionCheckpoints — 15 秒心跳快照

| 列 | 说明 |
|---|---|
| SessionId | 外键，级联删除 |
| CapturedAtUtc / EffectiveSeconds / State | 每 15 秒记一次「到此为止专注了多久、当时什么状态」 |

崩溃后恢复窗口用它估算已专注时间：**崩溃最多丢 15 秒**，且关机期间的时钟差不会算进专注时间（心跳之间才有效）。只保留最近 50 条。

### ProjectApplications — 项目配了哪些辅助程序（v2 新增）

| 列 | 说明 |
|---|---|
| ProjectId | 外键 → Projects，级联删除 |
| ApplicationId | 外键 → Applications，级联删除 |
| SortOrder | 显示顺序 |
| AddedAtUtc | 什么时候配上的 |

`UNIQUE(ProjectId, ApplicationId)`：同一个程序在同一个项目里只会有一条。这张表是**多对多**——一个项目可以挂多个程序，一个程序也可以被多个项目用。它记录的是「这个项目平时要用哪些程序」，下一次开始这个项目时会自动带进会话。

### SessionApplications — 这一轮实际用了哪些程序（v2 新增）

| 列 | 说明 |
|---|---|
| SessionId | 外键 → FocusSessions，级联删除 |
| ApplicationId | 可空；应用被删时置 NULL（不删这条快照） |
| NameSnapshot / ProcessNameSnapshot | **当时的名字和进程名**，应用后来改名或被删掉也不影响历史记录 |
| IsPrimary | 1 = 本轮主程序，0 = 辅助程序 |
| AddedAtUtc | 加进来的时间 |

为什么不直接靠 `FocusSessions.PrimaryApplicationId` + `ProjectApplications` 反查：项目配置会变、应用会被删，而「那一轮到底用了什么」是历史事实，必须冻结下来。所以会话开始时写快照，运行中加辅助程序时也追加一条。

`IsPrimary = 1` 的那条不能被当辅助程序移除（`SessionService.DetachAuxiliaryApplication` 会拒绝）。

## 4. 迁移规则（以后升级数据库怎么做）

写在 `DatabaseService.Initialize()` 里，`tests/.../Initialize_UpgradesV1DatabaseToV2_KeepingData`（v1→v2 真实升级）和 `MigrationRehearsal_V2ToV3_FollowsDocumentedRules`（v2→v3 流程演练）实测过整套流程：

1. `TargetSchemaVersion` 加 1，写一个 `ApplyV2()`（沿用 `CREATE TABLE IF NOT EXISTS` / `ALTER TABLE` 风格）。
2. 程序启动发现库版本 < 目标版本：**先自动备份**（标签「升级前-v旧版本」），再逐级执行迁移，最后更新 `user_version`。
3. 数据库版本 > 程序认识的版本（比如用旧 exe 打开新库）：**拒绝打开**，提示用户升级程序——绝不猜着往下跑。

## 5. 备份与恢复

- 备份用 SQLite 的 `VACUUM INTO`：生成一份**一致性快照**（WAL 里的内容也合并进去），不用先停写。文件名 `{库名}-{时间戳}-{标签}.db`，同名自动加序号，绝不覆盖。
- 恢复就是拿备份文件顶替主库（先关闭程序、连 `-wal`/`-shm` 一起处理）。`tests/.../Backup_RestoreRecoversData` 实测：写数据 → 备份 → 删主库 → 用备份顶上 → 数据完整可读。

## 6. 常用排查命令

用任何 SQLite 工具打开 `focus.db` 都行（WAL 模式建议复制三个文件后再打开）：

```sql
PRAGMA user_version;                                  -- 当前库结构版本
SELECT Name, TotalEffectiveSeconds FROM Projects;     -- 项目与累计秒数
SELECT Status, COUNT(*) FROM FocusSessions GROUP BY Status;
```
