# 架构说明

> 面向初学者：这个程序怎么组织的、为什么这么组织、几条关键链路怎么跑。

## 1. 总体结构：三层 + 一个系统层

```
界面层  FocusManager.App (WPF)
          Views / ViewModels / Themes
              ↓ 只调用服务
业务层  FocusManager.Core (纯 C#，无界面依赖)
          Services / Models / Time
              ↓ 只通过 DatabaseService
数据层  Microsoft.Data.Sqlite + Migrations
              ↓
系统层  Native/ (P/Invoke: 前台窗口、全屏、托盘、DWM)
```

依赖方向单向：上层知道下层，下层不知道上层。**Core 完全不认识 WPF**，所以计时、会话、统计这些业务逻辑可以脱离界面做单元测试（181 项里绝大多数测的是 Core）。

代码分布：

| 目录 | 内容 |
|---|---|
| `src/FocusManager.Core/Models` | 9 个数据模型 |
| `src/FocusManager.Core/Data` | DatabaseService（连接/迁移/备份）、Migrations |
| `src/FocusManager.Core/Services` | 10 个业务服务（计时、会话、项目、统计、应用、设置、白名单、提醒策略……） |
| `src/FocusManager.Core/Time` | ITimeSource / SystemTimeSource / TimeFormatter（时间可注入假时钟） |
| `src/FocusManager.App/Views` | 4 个页面 + 10 个对话框 |
| `src/FocusManager.App/ViewModels` | FocusViewModel / ProjectsViewModel / ApplicationsViewModel |
| `src/FocusManager.App/Services` | 依赖 Windows 的 7 个服务（前台监听、托盘、单实例、激活应用……） |
| `src/FocusManager.App/Native` | WindowsApi（P/Invoke）、FullscreenDetector、ForegroundHelper、DwmHelper |
| `src/FocusManager.App/Themes` | Tokens / Light / Dark / Icons / Controls（全手写样式，无第三方 UI 框架） |
| `tests/FocusManager.Tests` | 15 个测试文件 + FakeTimeSource / TempDatabase |

## 2. 启动流程（App.xaml.cs OnStartup）

1. **Velopack 钩子最先执行**：`VelopackApp.Build().Run()` 接收安装器传来的首次安装/更新后重启等参数。
2. **单实例检查**：`SingleInstance.Acquire()`（Named Mutex + 命名事件）。不是第一个实例 → 叫醒已有窗口后自己退出。
3. **数据目录三级回退**（AppPaths）：`%LOCALAPPDATA%\ProjectFocusManager\data` → `%APPDATA%\...` → exe 同目录 `data\`，每级都要真实写入探针文件才算数；三级全失败则弹窗列出尝试过的路径后退出。
4. **数据库初始化**：检查版本、必要时先备份再迁移。
5. **恢复检查**：发现上次未正常结束的会话 → 弹恢复窗口（继续 / 按已保存内容结束），关机时间不会算进专注。
6. 主窗口显示，托盘图标创建。

## 3. 计时链路（最核心的一条）

```
FocusTimerService（Stopwatch 单调时钟，分段记录，不碰数据库不碰界面）
        ↓ 心跳
SessionService（会话生命周期：开始/暂停/恢复/结束/异常恢复/心跳落库）
        ↓
DatabaseService → FocusIntervals（每段有效专注 = 唯一真相）
```

- `Stopwatch` 是单调时钟：改系统时间、休眠都不影响计时。界面每 200ms 只是读一次显示，**不做倒计时累加**（会漂移）。
- 每 15 秒往 `SessionCheckpoints` 写一条心跳，崩溃最多丢 15 秒。
- 有效时间 = 各段 FocusIntervals 之和；`FocusSessions.EffectiveSeconds` 和 `Projects.TotalEffectiveSeconds` 都只是缓存，随时可重算。
- 时间源做成接口（ITimeSource），测试里注入假时钟就能测「关机 2 小时不计时」「系统时间跳变」这类用例。

## 4. 前台监控与提醒链路

```
ActiveWindowMonitor（SetWinEventHook 事件驱动 + 5 秒低成本兜底）
        ↓ 前台窗口变了
FocusGuardService（进程名 → FocusGuardPolicy 状态机）
        ↓ 「离开了允许环境」
FocusViewModel → 强制置顶提醒一次（非模态）
        ↓ 用户选「确认切换」
暂停（必填原因）或结束
```

- 需求禁止高频轮询：实时靠 WinEvent 事件，兜底定时器只比较「句柄/全屏状态是否变化」，并且**跳过自己进程的窗口**。
- 全屏判定三个条件：铺满显示器矩形（不是工作区）+ 无标题栏边框 + 未被 cloak。只看「最大化」会把普通最大化误判。
- 提醒是 4 状态状态机（Normal / UnauthorizedDetected / ReminderShown / UserConfirmed）：同一段未授权只提醒一次，避免「提醒窗口自己抢前台 → 触发重新提醒」的死循环。
- **激活学习软件绝不 Process.Start**——只激活已经在运行的，防止程序偷偷替用户打开软件。

### 暂停 5 分钟提醒的激活子链（2026-11 修过一次卡死）

```
暂停满阈值 → PauseReminderWindow「该回来了」
        → 点「回到项目」→ ApplicationActivator.Activate
        → ForegroundHelper.ForceActivate（SetForegroundWindow 后轮询 5×50ms 确认真到前台了）
              失败回退①：最小化再还原（IsZoomed 记录状态 → SW_MINIMIZE → SW_MAXIMIZE/RESTORE）
              失败回退②：SwitchToThisWindow
        → 还失败 → AppNotRunningWindow 对话框
              「我已打开，继续专注」重试 / 「直接继续计时」跳过激活继续计时
```

背景知识：Windows 规定**后台进程不能随便抢前台**（SetForegroundWindow 会被静默忽略），这是系统防打扰机制，不是出错。所以激活后必须轮询确认、失败后多级回退，且必须给用户留「直接继续计时」的出口，不能让人被困在对话框里。

## 5. 单实例与窗口唤醒

- `Local\` 前缀的 Named Mutex 持有到退出为止；第二个进程发现拿不到锁，通过命名事件叫醒第一个实例，然后立刻退出。
- 唤醒回调里弹「已经开着了」提示时做了去重：已有提示框就更新内容并激活，不再叠加新窗口。

## 6. 内置 ChatGPT（WebView2）

- 启动时**不**初始化 WebView2（实测启动后浏览器进程数为 0），点「打开 ChatGPT」才创建。
- 整个程序只有一份浏览器环境；离开页面/点关闭就释放控件，浏览器进程随后归零（约 10 秒回收窗口，见 `docs/内存测试结果.md`）。
- 用户数据独立放在 `数据目录\WebView2\`，登录状态保留，程序不读取、不保存对话内容。

## 7. 界面与主题

- 全部手写 Style + ControlTemplate + `Path` 自绘图标：不引第三方 UI 框架（启动开销和内存都超预算），图标不依赖 Win10 没有的 `Segoe Fluent Icons`。
- 浅色/深色双主题，主题偏好存数据库；深色时连标题栏（DWM）一起变深。
- 高 DPI：app.manifest 声明 PerMonitorV2，混合缩放下文字不模糊（本机 100% 缩放实测，多显示器未测）。

## 8. 打包与分发

- `dotnet publish -r win-x64 --self-contained`：自包含发布，目标机器不需要装 .NET。
- Velopack（vpk 1.2.161）打成用户级安装包：免管理员权限、装到 `%LOCALAPPDATA%\ProjectFocusManager`，自带 Update.exe 支持增量更新；Portable.zip 是免安装版。
- 程序通过 `VelopackApp.Build().Run()` 接收安装器钩子；数据库与程序目录分离，升级不丢数据。

## 9. 测试策略

- Core 层：181 项 xUnit 测试（约 1 秒跑完），计时准确性、会话生命周期、白名单语义、随手记、备份恢复、迁移演练都有可复现用例。
- App 层（窗口、托盘、前台监听）：零自动化测试，靠 `.tools/screens/` 下的 PowerShell + UIAutomation 脚本实测（脚本不进仓库）。
- 详见 `docs/测试报告.md`。
