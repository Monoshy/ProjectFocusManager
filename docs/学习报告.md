# 初学者学习报告

> 写给自己：做完这个项目，到底学到了什么。不只是「会用什么」，还有「踩过什么坑、为什么会那样」。

## 1. 这个项目是什么

一个 Windows 桌面专注管理工具：以「项目」为中心正向计时，切到不该用的软件只提醒不强制，带随手记、统计、托盘、内置 ChatGPT。完全本地运行，最终打成了免管理员的用户级安装包。从环境审查到安装包，共 6 个阶段，最终约 12,700 行代码、181 项自动化测试。

## 2. 学到的技术，按「真用到才懂」排序

### C# / .NET

- **三层架构不是背概念**：Core 不引用 WPF，业务逻辑才能用纯 xUnit 测试。一旦 Core 里混进一行 `MessageBox.Show`，测试就再也跑不起来了。
- **面向接口测试时间**：把「现在几点」做成 `ITimeSource`，测试注入假时钟，就能测「关机 2 小时不计时」「系统时间跳变」——真实时钟根本没法测。
- **P/Invoke**：SetForegroundWindow、SetWinEventHook、DWM、PrintWindow，全是查 Win32 文档学着声明的。明白了「托管世界」和「Windows 世界」之间的桥怎么搭。
- **WPF 手写样式**：没引 UI 框架，Style/ControlTemplate/Path 图标全手写。懂了为什么第三方框架省事但也偷走了启动速度和内存。

### Windows 机制（最大的收获区）

- **前台锁定（Foreground Lock）**：后台进程调 `SetForegroundWindow` 会被 Windows 静默忽略——这是防打扰机制，不是 bug。修复暂停提醒卡死 bug 时真正搞懂了：调用后必须轮询确认、失败要多级回退（最小化再还原、SwitchToThisWindow）、且永远给用户留手动出口。**「程序没坏，是系统规则如此」这种认知，只有被坑过才有。**
- **全屏 ≠ 最大化**：要三个条件一起判（铺满显示器矩形 + 无边框 + 未 cloak），任何一个单独用都会误判。
- **单实例**：Named Mutex + 命名事件，`Local\` 前缀限制会话；比想象中简单，也比想象中容易漏（锁必须持有到退出）。

### 数据

- **WAL 模式**：`VACUUM INTO` 能在不停止写入的情况下拿到一致性快照——备份不一定要停机。
- **唯一真相 + 缓存**：专注秒数以 FocusIntervals（段）为唯一真相，会话表和项目表里的数字都是缓存。缓存坏了不可怕，随时能重算。这个思路适用于一切有冗余的存储。
- **迁移纪律**：`PRAGMA user_version` + 升级前自动备份 + 拒绝打开更高版本库。用「预演测试」把未来 v2 升级提前演练了一遍。

### 打包与发布

- **自包含发布**：`dotnet publish -r win-x64 --self-contained`，目标机器免装 .NET，代价是 138MB。
- **Velopack**：用户级安装、免管理员、自带增量更新。学到「安装器会占用 `%LOCALAPPDATA%\<应用名>` 目录，所以数据目录要留出 `/data` 子目录」——这类坑不真打一次包根本想不到。
- **NuGet 离线化**：网络受限时，nupkg 本质是 zip，curl 下载塞进本地包源 + `nuget.config` 指过去，dotnet 照样还原。

## 3. 踩过的坑（每条都有血泪）

1. **环境比代码难**：SDK 要装进项目目录、`%TEMP%`/`%LOCALAPPDATA%` 被 ACL 拒绝、PowerShell 5.1 读无 BOM 文件把中文读坏、`.slnx` 不是 `.sln`……「写代码之前先把环境搞明白」这句话值一小时一学费。
2. **测试环境里连 winver.exe 都比记事本好用**：Win11 记事本是系统托管应用，拿不到主窗口句柄——测窗口激活时差点钻进死胡同。
3. **「有代码」≠「已验证」**：PROJECT_STATUS 里最反复强调的一句话。暂停提醒弹过了，不等于激活链路不会把用户困在对话框里。
4. **测量点会撞上回收窗口**：关网页 4 秒后测内存显示还有 300MB「泄漏」，每 2 秒测一次才发现 10 秒后进程真的归零。**单点测量会撒谎，时序测量才接近真相。**
5. **UIA 不是万能探针**：模态 owned window 枚举不到、未展开的 ComboBox 返回 0 个列表项——自动化验证要准备好 Win32 后备手段。
6. **界面布局条件反射会骗人**：`GetWindowRect` 在最小化时返回 160×32；截图用 PrintWindow 而不是抢前台。

## 4. 方法论层面的心得

- **每次改动一个 commit、每次改动配测试**（AGENTS.md 就两条规则）：回头看 git log 就是完整的开发史，`git revert` 永远有退路。
- **交接文档是写给三个月后的自己的**：PROJECT_STATUS.md 坚持「为什么这么做」和「哪些没验证」都写下来，这次收尾阶段直接照着它干活，零回忆成本。
- **限制催生设计**：因为要求「不打扰学习」，才有了状态机提醒、绝不自动启动软件、非模态提醒这些设计。需求里的每个「不」字都对应一个技术决策。
- **如实记录失败**：内存目标没达成（<60MB 放弃）、安装流程本机验不完——写进报告比藏起来有用，下一个读文档的人（包括未来的我）需要知道边界在哪。

## 5. 如果重来一次

- 一开始就建 `nuget.config` 和环境脚本，不要等第一次网络失败。
- App 层早点引入轻量 UI 自动化（哪怕只是 FluentAutomation 脚本化），不留到最后手工验证。
- 数据目录策略（安装器占用哪个目录）应该在选打包方案时就确定，而不是打包时才对齐。

## 6. 下一步可以学的

- UI 自动化测试框架（FlaUI / WinAppDriver），把 App 层测试空缺补上
- Velopack 的发布通道与增量更新实测（需要一台 `%LOCALAPPDATA%` 正常的机器）
- WPF 的 x:Bind / MVVM Toolkit（本项目手写了 ViewModel 通知，框架能省不少样板代码）
